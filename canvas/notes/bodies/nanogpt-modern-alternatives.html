So what actually makes modern LLMs better?

Not the vibes. Not the benchmarks. The actual mechanisms — the architectural choices that separate GPT-2 from LLaMA 3 from DeepSeek V3. I wanted to see each one, not just read about it in a paper.

So I took Andrej Karpathy’s nanoGPT, a beautifully minimal ~300-line GPT implementation and decided to work on it. One component at a time. Measuring loss after every cut.

By the end, I had built what I’m calling nanoLLaMA: a tiny model that stacks every quality-improving architecture trick from the last three years into a single, readable codebase. And I have the receipts.

nanoGPT

Karpathy’s nanoGPT is a thing of beauty. It’s a clean GPT-2 implementation you can read in an afternoon. Transformer blocks with LayerNorm, GELU activations, learned positional embeddings, standard multi-head attention.

I set up a fixed benchmark: a 4-layer, 4-head, 128-dimensional model trained on Shakespeare character-level data for 2000 iterations. Small enough to run on CPU in minutes. Same seed every time. Val loss = pure next-token cross-entropy.

Baseline val loss: 1.6645

Everything is measured against this.

Cut 1: RMSNorm — The Easy Win

LayerNorm computes a mean and variance, then re-centers and rescales. RMSNorm throws away the mean-centering and just divides by the root-mean-square. That’s it.

class RMSNorm(nn.Module):
    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).add(1e-6).rsqrt()
        return x * rms * self.weight

Result: 1.6589 (−0.006)
Marginal improvement. The real gain is efficiency, fewer operations per forward pass.

Cut 2: SwiGLU — Where Things Get Interesting

The standard MLP in a transformer is: Linear → GELU → Linear. Two projections. SwiGLU uses three projections:

gate = Linear(x)
up = Linear(x)
output = down(SiLU(gate) * up)

The gate acts like a learned filter. Instead of just activating neurons, you’re learning which neurons even matter for a given input. The result is a more expressive MLP with the same parameter budget.
One gotcha: hidden dim. The standard MLP uses 4 × d_model. To keep params roughly equal with three projections, SwiGLU uses ⅔ × 4 × d_model. (And you need to round to a hardware-friendly multiple — I used 64, not 256, or you accidentally inflate params by 30%.)
Result: 1.5897 (−0.075 from baseline)

Cut 3: RoPE — Giving the Model a Sense of Time

Learned positional embeddings (like nanoGPT uses) have a problem: they memorize positions during training. Positions outside the training context length are a mystery.

Rotary Position Embeddings (RoPE) encode position geometrically, by rotating query and key vectors in 2D subspaces. The rotation angle is a function of position. Crucially, the relative angle between position 3 and position 7 is the same whether you’re near the start or deep into a long document.

def apply_rotary_emb(x, cos, sin):
    return x * cos + rotate_half(x) * sin

No extra parameters. No positional embedding table. Just a mathematical property baked into how Q and K interact.
Result: 1.5641 (−0.100 from baseline)
The largest single-component improvement. RoPE earns its spot in every modern architecture.

Cut 4: Grouped Query Attention — Cheaper Inference

Standard multi-head attention (MHA) has N query heads and N key-value heads. At inference, you cache all of them. For a 70B model, that KV cache can be tens of gigabytes.

GQA splits the difference: fewer KV heads, full Q heads. A group of query heads share one KV pair.

# Each KV head serves 2 query heads
n_head = 4 (query heads)
n_kv_head = 2 (key-value heads)

Before attention, you expand K and V with repeat_interleave.
Result: 1.6863 (+0.022)
Slightly worse accuracy — each query head has less unique key/value information. But: 2× smaller KV cache. At 70B scale with long contexts, this is worth every point.

Cut 5: Multi-Head Latent Attention — DeepSeek’s Secret Weapon

GQA reduces KV heads. MLA does something more radical: it compresses K and V into a single low-dimensional latent vector.

c_KV = kv_down(x)          # compress: [d] → [r], r << d
K    = k_up(kv_norm(c_KV))
V    = v_up(kv_norm(c_KV))

At inference, you only cache c_KV — not full K and V. Then you reconstruct K, V on the fly. DeepSeek V2/V3 uses this to get an 8× KV cache reduction vs standard MHA.

Result: 1.8067 (+0.142)

Worse than baseline on this tiny model, at this tiny scale. MLA’s compression ratio is aggressive for 128-dimensional embeddings — the bottleneck squeezes too hard. At scale (where kv_lora_rank is large relative to the compression benefit), it shines. This is an important lesson: not every technique works at every scale.

Cut 6: Mixture of Experts — Conditional Computation

Dense LLMs activate every parameter for every token. MoE changes this: you have N independent MLPs (“experts”), and a router selects only the top-K for each token.

router_logits = self.router(x)  # [B, T, n_experts]
topk_weights, topk_idx = router_logits.topk(top_k)

With 4 experts and top-2 routing: every token uses 2 MLPs, but you have 4 to choose from. The model can specialize — different experts for syntax, semantics, rare words, common phrases. There’s a catch: experts can collapse. The router might learn to always pick the same 2 experts and ignore the rest.

The fix is an auxiliary load-balancing loss:

L_aux =α × E × Σ(f_i × p_i)

Where f_i is the fraction of tokens routed to expert i, and p_i is the average routing probability. This penalizes imbalance.

Result: 1.6321 (−0.032 from baseline)

Better than baseline with effectively the same compute per token. At scale, MoE lets you have a 400B parameter model with 40B active parameters. That’s the DeepSeek formula.

Cut 7: Multi-Token Prediction — Denser Training Signal

Standard language model training: predict the next token. MTP: predict the next N tokens simultaneously.

for i, head in enumerate(self.mtp_heads):
    offset = i + 2  # predict t+2, t+3, ...
    aux_logits = head(x[:, :-offset])
    aux_loss += cross_entropy(aux_logits, targets[:, offset-1:])

Same forward pass. Same inference (MTP heads are only active during training). But each training step is richer — the model must be consistent about multiple future positions, not just the immediate next token. Meta uses this in their latest research.

Result: 1.6353 (−0.029 from baseline)

The gain seems small in 2000 iterations. But at longer training runs,MTP is reported to accelerate convergence significantly. The model learns more from each token it sees.

The Finale: All of It Together

Stack them all: RMSNorm + SwiGLU + RoPE + MoE (4 experts, top-2) + MTP (4 heads).

norm_type = ‘rmsnorm’
mlp_type = ‘swiglu’
pos_type = ‘rope’
n_experts = 4
moe_top_k = 2
mtp_depth = 4
mtp_loss_coeff = 0.3

Result: 1.5259 (−0.139 from baseline)
And more importantly — it converges faster. The nanoLLaMA stack reached baseline’s final val loss (1.6645) by around step 500, while the baseline doesn’t get there until step 1500–2000.

What I Learned

The quality winners: RoPE > SwiGLU > MoE > MTP > RMSNorm. If you only add one thing, add RoPE.

The efficiency winners: GQA and MLA trade a little quality for massive KV cache savings. At scale, this trade is often worth it — the difference between a model that fits in GPU memory and one that doesn’t.

MLA’s lesson: Low-rank compression only works when the compression ratio is reasonable. On a 128-dim toy model, you’re bottlenecking too aggressively. The idea is sound; the scale matters.

A caveat on “synergy”: The combined improvement (0.139) is less than RoPE (0.100) + SwiGLU (0.075) alone (0.175). So these components aren’t magically amplifying each other — there’s overlap in what they improve. That said, the combined stack still outperforms any individual component, and the convergence speed improvement is real.
