Mycelium

Agent reliability runtime · 30k PyPI downloads · Open source

I built Mycelium to handle a practical problem: an agent retries a tool call, but the first attempt may already have changed something. The runtime tracks actions and outcomes so it can reuse a completed result, wait for ongoing work, or stop an uncertain retry. It works with LangGraph, CrewAI, and custom Python agents.

Read the architecture · Read docs · See a retry failure example · View source · Install from PyPI · Download stats

How it works
Agent loop → Mycelium guards → Tool execution

Mycelium sits between the agent loop and tools. mycelium init / mycelium run wrap configured callables from YAML, while decorators and manual claim/execute/complete flows remain available. File, SQLite, Redis, and PostgreSQL ledgers persist leases, side-effect boundaries, and terminal outcomes. Tests cover process crashes, multi-worker races, storage outages, reconciliation, and operator release. It does not claim to solve hallucination, prompt injection, or general goal alignment.

vLLM-style LLM Serving on Apple Silicon

LLM inference infrastructure

I built a local LLM serving engine on Apple Silicon using MLX. It handles concurrent requests with continuous batching and PagedAttention-inspired KV cache management, and exposes OpenAI-compatible chat completions. The repository includes benchmarks against vLLM and llama.cpp.

View source · Read architecture

How it works

Request scheduling is decoupled from token generation so new requests can join active batches. Paged KV blocks and prefix reuse reduce memory waste and repeated prefill work.
